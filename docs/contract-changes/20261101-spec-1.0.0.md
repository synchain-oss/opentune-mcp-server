# Contract change: release the OTCP specification as 1.0.0

- Date: 2026-11-01
- Frozen surface: `spec/otcp/v1/PROTOCOL.md`, `spec/otcp/v1/README.md`, `spec/otcp/v1/CHANGELOG.md` (wording only)
- Specification version: `1.0.0-rc.9` becomes `1.0.0`; wire version unchanged (`1.0`). The tag `spec-v1.0.0` does not
  exist yet; the maintainers set it after this change is merged.

## Background

`1.0.0-rc.9` was proposed as the text of 1.0.0, and the control interface is to be proposed to the OpenTune project,
which should receive a released version of the specification rather than a release candidate. This change makes the
text of rc.9 the release: it removes the word "draft" from the status lines and rewords the two sentences that referred
to "this release candidate", so that they still mean the same thing once the text is no longer one.

## Changes

| File                        | Change                                                                                                                                                                                                                                                               |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `spec/otcp/v1/PROTOCOL.md`  | Status line: `1.0.0-rc.9`, draft, becomes `1.0.0`. Section 19 rule 11: "an implementation of this release candidate" becomes "an implementation of version 1.0". Section 20.4 rule 3: "written before this release candidate" becomes "written before `1.0.0-rc.9`". |
| `spec/otcp/v1/README.md`    | Current version: `1.0.0-rc.9` (draft) becomes `1.0.0`.                                                                                                                                                                                                               |
| `spec/otcp/v1/CHANGELOG.md` | New section `1.0.0` dated 2026-11-01.                                                                                                                                                                                                                                |

No schema, vector, registry entry or method changes. The rule of section 19 rule 11 keeps its leniency (a server may
still send those export errors without a reason, and clients rely on the error kind and `retryable`); the rule of
section 20.4 rule 3 keeps its meaning (rc.9 introduced the per-target media folder).

## Compatibility

None needed: no wire format, schema or vector changes, so a client or server of `1.0.0-rc.9` interoperates with one of
`1.0.0` exactly as before. The copy of the specification in the OpenTune fork follows in a separate change that locks
the tag `spec-v1.0.0`.
