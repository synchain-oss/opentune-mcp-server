# Contract change: write result rendering golden snapshots

## Background

Every tool that returns an OTCP write envelope hands it to `src/render/`, which adds a one-sentence summary, the
effects visible in the OpenTune window, a table of the changes and one line each for warnings, side effects and the
undo or revert recipe. The sentences come from fixed tables, not from OpenTune, so their wording is a contract with
the model that reads them. This change freezes it with golden snapshots, one per scenario.

## Files

| File                                         | Change                                                                                                                                         |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `test/golden/render/*.json`                  | New. Per scenario: the tool, the write envelope that was rendered and the body produced. Generated by `npm run catalog:update`.                |
| `test/unit/render-golden.test.ts`            | New. Compares the scenarios with the files; `catalog:update` rewrites them.                                                                    |
| `src/tools/registry.ts`                      | `uiEffects`, `changeTable` and `lines` are added to the members of the shared write-result outputSchema (still top-level keys only, no enums). |
| `package.json`, `scripts/update-catalog.mjs` | `test:catalog` and `catalog:update` also run the rendering snapshots.                                                                          |

The OTCP specification (`spec/otcp/v1/`) and the tool catalog are not changed.

## Compatibility

No tool uses the renderer yet, so no client sees the new members until a write tool is added. The members are
additions to the result; a client that ignores them still finds the complete envelope unchanged next to them.
