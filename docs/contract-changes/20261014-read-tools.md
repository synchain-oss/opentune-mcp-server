# Contract change: read tools opentune_get_project and opentune_get_notes

## Background

This change adds the first two tools that read project state: `opentune_get_project` and `opentune_get_notes`. They
extend the frozen `tools/list` catalog, so `test/golden/tools-list.json` and the generated `docs/reference.md` change.
The OTCP specification (`spec/otcp/v1/`) and the MCP instructions are not changed.

## Files

| File                          | Change                                                                                                                |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `test/golden/tools-list.json` | Two entries appended in registry order: `opentune_get_project`, `opentune_get_notes`. Existing entries are unchanged. |
| `docs/reference.md`           | Regenerated by `npm run catalog:update`.                                                                              |
| `scripts/gates.mjs`           | The `output budget` check no longer skips: it runs `npm run test:budget`.                                             |
| `package.json`                | New script `test:budget`. No dependency or lifecycle-script change.                                                   |

## Tool surface

| Tool                   | Input                                                                                                  | OTCP methods                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------- |
| `opentune_get_project` | `track_ids?`, `include_history?`, `instance_id?`                                                       | `project.get`, `edit.getHistory` (on request) |
| `opentune_get_notes`   | `clip`, `clock` (required), `from?`, `to?`, `cursor?`, `limit?` (default 100, max 200), `instance_id?` | `content.getNotes`, `project.get` (geometry)  |

Both are read-only (`readOnlyHint: true`, `openWorldHint: false`) and need the `read.v1` capability.

## Result shape

- Each clip in `opentune_get_project` carries one opaque `clip_revision`, and the result one `arrangement_revision`. They
  replace the per-aspect OTCP tokens (`revision`, `gridRevision`, `keyRevision`, `geometryHash`, `arrangementRevision`),
  which the tools no longer show. Write tools take them back as `expected_revision` and forward only the aspects the
  operation depends on, so a change of another aspect does not conflict (`src/otcp/tokens.ts`).
- `opentune_get_notes` returns the notes as OTCP reports them, without the display-only `label`, plus `clip_revision`,
  `next_cursor` (the OTCP cursor, unchanged) and `range`. The clock is stated by the caller and by the member names.
- A single result of either tool stays within 20,000 characters. When a page of notes would exceed that, the tool
  reduces the page size (never cuts a page), says so in `summary` and `page_limit_applied`, and `next_cursor` continues
  exactly where the page ends.

## Compatibility

There is no earlier version of these tools. The shape of `clip_revision` and `arrangement_revision` is private to this
server; clients treat them as opaque strings and must not parse them. Tool names freeze with the first npm release.
