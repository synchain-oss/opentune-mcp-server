# Contract change: the reference alignment is retired (OTCP specification 1.0.0-rc.7)

- Date: 2026-10-26
- Frozen surface: `spec/otcp/v1/**`, `test/golden/**`
- Specification version: `1.0.0-rc.6` → `1.0.0-rc.7` (wire version `1.0`, unchanged), proposed as the text of 1.0.0.
  The tag `spec-v1.0.0-rc.7` is set by the maintainers after approval.
- Implementation lines changed with it: `mock/**`, the tools `opentune_autotune_range`, `opentune_get_clip_details`,
  `opentune_edit_arrangement`, `opentune_set_settings`, `opentune_get_settings`, `opentune_manage_ui`,
  `opentune_open_project`, `opentune_delete_track` and `opentune_cancel_job`, the result rendering and the retry tables
  in `src/`, and the tests, goldens and end-to-end tour that exercised the feature.

## Background

OpenTune's upstream project retired the experimental reference track: a clip could be bound to a reference clip, OpenTune
analysed the reference in the background, and the AUTO Ref button then aligned the notes of the clip to it. The feature
and its button are gone from OpenTune, so the control interface has nothing left to read, write or report for it. The
specification, the mock and the tools remove it instead of keeping members that no OpenTune build can honour.

Protocol major 1 has only release candidates so far, and a release candidate may remove members (spec `README.md`,
"Versions"); from 1.0.0 on, a minor version only adds. The registries are the exception to removal: they only grow, so
the codes that were sent stay, marked as retired.

## Interoperability

Both versions are release candidates of the same wire version `1.0`. The only change a client can see is the removal of
members and of one method.

- A client of rc.6 with a server of rc.7 that sends a removed request member (`mode: "reference"` or `placementId` of
  `content.autoTune`, the op `setReference` of `arrangement.edit`, `referenceAlignMode` of `prefs.set`) gets
  `INVALID_ARGUMENT(invalid_params)` and nothing is changed, because a server rejects unknown or no longer valid params
  (section 2.3 rule 3). A call of `content.analyzeReference` gets `UNSUPPORTED(unknown_method)`. The results of the other
  methods lack the removed members; a client that read one of them as required has to treat it as absent.
- A client of rc.7 with a server of rc.6 sends none of the removed members and ignores the members that a server of
  rc.6 still puts into results (`reference`, `referencePlacementId`, `processing.referenceAlignMode` and the others,
  section 2.3 rule 1). An instance of rc.6 still reports the capability `reference.v1`; a client of rc.7 does not
  know it and ignores it, as it ignores every unknown capability.
- The registries keep the retired reasons and the warning, so a client of rc.7 that meets one from an older server still
  reads it by its error kind (section 2.3 rule 2). The retry tables of this server do not list them any more.
- Users of the 0.1.0 package: `opentune_autotune_range` no longer accepts `mode: "reference"` (`regenerate`, `snapNotes`
  and `notesOnly` are unchanged); `opentune_edit_arrangement` no longer accepts the op `set_reference`;
  `opentune_set_settings` no longer accepts `processing.reference_align_mode`; `opentune_get_clip_details` no longer
  offers the section `reference`. A call that names one of them is refused with `INVALID_ARGUMENT` before anything is
  sent, because the tool schemas reject them.
- OpenTune's implementation (the test build) is changed separately; until it drops the feature, a build of the previous
  version still answers the removed members. This server does not send them and ignores what the build reports about
  them. Its copy of the specification and the runner are updated separately.

Open question for the maintainers: `reference.v1` is deleted from `registry/capabilities.json`, although registries only
grow. It was deleted because it is a literal value of the capability list of `session.info` that a build of rc.7 must not
report, and because no method of rc.7 needs it; the alternative is to keep it with `retiredIn: "1.0.0-rc.7"`, as the
reasons and the warning are kept.
