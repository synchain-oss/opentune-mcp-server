# Contract change: import and export tools opentune_open_audio and opentune_export_audio

## Background

This change adds the two tools that move audio in and out of OpenTune: `opentune_open_audio` (imports audio files as
new clips) and `opentune_export_audio` (writes a WAV file of a clip, a track or the master mix). They extend the frozen
`tools/list` catalog, so `test/golden/tools-list.json` and the generated `docs/reference.md` change. The OTCP
specification (`spec/otcp/v1/`) and the MCP instructions are not changed.

Both tools accept paths, so this change also adds the path handling that every tool accepting a path uses
(`src/paths/`, `src/sanitize/path-input.ts`).

## Tool surface

| Tool                    | Input                                                                                                                                                                                 | OTCP methods                             |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| `opentune_open_audio`   | `path` or `items[]` (one of them), `layout?`, `track?`, `start?`, `new_track?`, `generate_notes?`, `focus?`, `allow_duplicate?`, `wait_seconds?` (default 25, max 30), `instance_id?` | `import.start`, `job.get`                |
| `opentune_export_audio` | `kind` (`clip`, `track`, `master`), `target?` (`{clip}` or `{track}`), `path?`, `allow_dry?`, `wait_seconds?` (default 25, max 30), `instance_id?`                                    | `export.start`, `project.get`, `job.get` |

Both write results (`readOnlyHint: false`, `openWorldHint: false`) and share the write-result `outputSchema`. They need
the capabilities `import.v1` or `export.v1`, and `jobs.v1`.

## Behaviour

- **Paths.** A path is cleaned (quotes, invisible marks), then normalized (`file://`, `~`, `/mnt/<drive>/` to
  `<drive>:\` on Windows, forward slashes to backslashes on Windows), then checked against the rules of
  `spec/otcp/v1/PROTOCOL.md` section 20.1. Relative, UNC, `\\?\`, `\\.\`, drive-relative paths and alternate data
  streams are refused with `INVALID_ARGUMENT` and the OTCP reason, before any request. The error never repeats the
  path. OpenTune's own checks stay authoritative.
- **Import.** The files and the target give the idempotency key (`otmcp-import-` and a SHA-256 prefix), so repeating the
  call returns the same job and imports nothing again; `allow_duplicate` sends no key. The tool waits for the job up to
  `wait_seconds`; if it has not ended, the result is the start envelope that names the job, to be followed with
  `opentune_get_job`. When it has ended, the job's write envelope is rendered; failed items are counted in the summary
  and listed in `items[].error`. Notes that OpenTune generated for the focused clip in the openDyne scheme are named in
  the summary (and in the side-effect line).
- **Export.** There is no overwrite option: the call always sends `ifExists: rename`, so a taken name gets the next free
  one (`name (2).wav`). The target must end in `.wav`. Without `path` the file is `<source folder>/<source name>.opentune.wav`
  (clip: its source; track: the source of its first clip; master: the saved project's name, else the first clip). A
  path equal to a source file of a clip is refused before the job starts (`target_is_loaded_media`); OpenTune decides by
  file identity and stays authoritative. When `dryContents` is not empty, the first sentence of the summary says so.
- **Errors.** `ANALYSIS_FAILED` (suggests `allow_dry` only with the user's agreement), `RENDER_FAILED`,
  `BUSY(export_in_progress)` and `NOT_READY(export_wait_timeout)` carry a next step.

## Compatibility

The change only adds tools and error next steps. Existing tools, their schemas and their golden entries are unchanged.
A client that does not know the new tools is unaffected. The tools call only methods and reasons that exist in
OTCP v1; an OpenTune build without `import.v1`, `export.v1` or `jobs.v1` gets `UNSUPPORTED(capability_missing)`.
