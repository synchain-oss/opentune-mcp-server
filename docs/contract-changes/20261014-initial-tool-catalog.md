# Contract change: initial tool catalog

## Background

This change registers the first tools and so creates two frozen surfaces that did not exist before: the `tools/list`
catalog and the MCP instructions. From now on both are compared byte for byte with golden snapshots by the unit tests,
by the stdio smoke test (catalog only) and by the `tools/list size gate` of `npm run gates`, which runs the built
bundle. `docs/reference.md` is generated from the same registry and checked by the `docs consistency` gate.

## Files

| File                           | Change                                                                                              |
| ------------------------------ | --------------------------------------------------------------------------------------------------- |
| `test/golden/tools-list.json`  | New. `tools/list` of `opentune_get_status` (alwaysLoad), `opentune_get_job`, `opentune_cancel_job`. |
| `test/golden/instructions.txt` | New. The MCP instructions sent in `initialize` and `server/discover` (1,298 characters).            |
| `docs/reference.md`            | New, generated by `npm run catalog:update`.                                                         |

The OTCP specification (`spec/otcp/v1/`) is not changed.

## Compatibility

There is no earlier catalog, so no client depends on a previous shape. The tool names follow the naming rule and
freeze with the first npm release; until then they may still change through a contract change like this one. A
later change to a golden file needs its own record in `docs/contract-changes/`.
