# Contract change: opentune_estimate_key

## Background

OpenTune detects the key of a clip from the vocal pitch alone and reports one key per clip, without candidates,
probabilities or a tuning offset. For pitch correction what matters is the set of seven notes the notes snap to: taking
C major for A minor changes nothing (relative keys share their notes), taking G major for C major moves one scale degree,
taking C minor for C major moves three. This change adds one read-only tool to the frozen `tools/list` catalog,
`opentune_estimate_key`, which estimates the key from the vocal pitch of a clip and from a WAV file of the mix or the
backing track, and separates the confidence in the scale set from the confidence in the tonic. The OTCP specification
(`spec/otcp/v1/`) and the MCP instructions are not changed; the tool calls existing read methods only. Existing catalog
entries are unchanged.

## Tool surface

Inputs: `clip?` (placement id `p:...` or content id `c:...`), `mix_path?` (absolute path of a `.wav` file), `sections?`
(1 to 16 time ranges `{start_sec, end_sec}`, each at least 2 s long) and `instance_id?`. At least one of `clip` and
`mix_path` is required. With `mix_path` alone no OpenTune instance is needed. With `clip` the tool needs `read.v1` and
calls `content.getDetails`, `content.getNotes` (all pages), `content.segmentNotes` (only when the clip has no stored
notes) and `content.getPitchCurve`; it decodes no vocal audio.

The WAV file is opened read-only: integer PCM of 16, 24 or 32 bits or 32-bit float, mono or stereo, plain or
`WAVE_FORMAT_EXTENSIBLE`, at most 256 MiB. Other formats, a file over the limit, a missing file and refused paths are
errors before any analysis (`INVALID_ARGUMENT` with `path_bad_extension`, `wav_unsupported`, `file_too_large`,
`not_a_file` or a path reason; `NOT_FOUND` with `file_not_found`; `IO_ERROR` with `read_failed`); the next step points
to converting the file or exporting a WAV with OpenTune. Error details never repeat the path.

Result members:

| Member                          | Content                                                                                                                                                   |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `candidates`                    | The 5 most probable keys: `root` (0 = C ... 11 = B), `scale` (`major` or `minor`), `name`, `probability`.                                                 |
| `scale_set_confidence`          | Probability of the best key plus its relative key: the seven notes are right.                                                                             |
| `tonic_confidence`              | Share of the best key within its scale set (0.5 = cannot tell it from the relative key).                                                                  |
| `scale_set`                     | The best key and its relative key, and `tonic_clear` (tonic confidence at least 0.75).                                                                    |
| `recommendation`                | `key` for `opentune_set_clip` (`key`) or `opentune_autotune_range` (`scale`), `ask_user`, `reason`; chromatic when the scale set confidence is below 0.6. |
| `tuning_offset_cents`, `tuning` | Offset from the A4 reference (`tuningHz` of the instance when a clip is given, else 440 Hz) of the vocals and of the mix, with their reliability.         |
| `sources`                       | For the mix, the bass line of the mix and the vocals: used or not (with the reason), effective weight, reliability and amounts.                           |
| `estimated_over`                | The time range the estimate covers: the whole song, or its longest part when the key changes.                                                             |
| `local_keys`                    | Keys over time (12 s windows every 4 s, Viterbi path with a cost per key change that grows with the distance on the circle of fifths).                    |
| `sections`                      | Only when asked: per range the 3 best keys, both confidences and the key to use.                                                                          |
| `clip`                          | With a clip: ids, the clip key as OpenTune reports it, and whether it has the same notes as the estimate.                                                 |
| `warnings`, `nullReasons`       | Tuning beyond 15 cents, vocals only, a frequent flat seventh, read limits, mix and clip of different lengths; reasons for every `null`.                   |

## Behaviour

- **Evidence.** The mix gives a harmonic pitch-class profile (spectral peaks, each also counted towards the notes of
  which it could be the 2nd to 4th harmonic) and a separate bass profile from the peaks below 200 Hz. The vocals give a
  histogram of the detected pitch of the notes, weighted by duration, the last note of a phrase counted 1.5 times. Each
  source is correlated with the major and minor profiles of Temperley's Kostka-Payne statistics (minor flat seventh
  raised to the weight of the leading tone) and the correlations are fused with base weights 0.6 (mix), 0.2 (bass) and
  0.2 (vocals), scaled by the reliability of each source. With the mix present, the vocals check the three best keys:
  a key whose scale leaves out more of the sung time loses score, which corrects the dominant and the parallel-minor
  confusions of the mix. Probabilities are a softmax whose sharpness follows the reliability.
- **Clocks.** Section times and local keys are seconds from the start of the mix file and of the clip's source audio,
  which are taken to start together; a warning says when their lengths differ by more than 2 s.
- **Untrusted strings.** OpenTune values (the clip key, the analysis state) are accepted only in their protocol forms;
  anything else becomes `null` or `unknown`. The summary is built from this server's own text.
- **Licensing.** The estimator is written from the published methods; no code of other key detectors is used, and the
  package keeps zero runtime dependencies.

## Compatibility

A client that does not know the new tool is unaffected: no existing tool, schema, result or the instructions change.
The tool talks to any OpenTune build that offers `read.v1`, through methods that exist since OTCP 1.0.
