# Features

**English** | [简体中文](features.zh-CN.md)

OpenTune MCP Server (by Synchain) lets an AI client operate OpenTune Standalone, the open-source AI vocal pitch-correction app. You tell the agent in plain words what you want ("pull the second phrase into tune", "move this section 30 ms earlier"); the agent calls the server's 28 tools, which do what a person can do in the OpenTune window, and every result says what changed (before and after, with units), what the side effects are, and whether and how it can be undone.

This page lists what you can ask for, grouped by purpose, with the tool behind each item and what to expect. It is a map of the tools, not a promise about sound: the numbers measure pitch only, the agent cannot hear, and you judge the result by listening. The exact parameters of every tool are in [reference.md](reference.md).

## What you need

- **An OpenTune build with the control interface.** The official OpenTune release does not have it yet, so the server works only with the [unofficial test build](https://github.com/synchain-oss/OpenTune/releases) of OpenTune (Windows x64). With an official OpenTune, `opentune_get_status` reports `NO_API_BUILD`. The test build uses the models of an installed official OpenTune (1.7.9 or newer). Set-up is in the [README](../README.md#install) and [install.md](install.md).
- **OpenTune Standalone only.** The OpenTune VST3/ARA plug-in inside a DAW is not covered; the exchange with a DAW is by file path.
- **A test build that is new enough for the feature.** Each tool declares the capabilities of the test build that it needs, and a tool whose capability is missing answers `UNSUPPORTED` with a next step; every other tool keeps working. The test build released with 0.2.0 is `synchain-test/v1.8.0-ctl.2` (specification `1.0.0-rc.8`); it includes closing OpenTune (`app.quit`), switching the view (`ui.workspace`) and autosave copies (`project.copy`). An older test build lacks the capabilities that came after it. See [COMPATIBILITY.md](COMPATIBILITY.md#capabilities-of-the-test-build).
- **A person for the first launch.** The first time OpenTune starts with a fresh data folder it shows a one-time welcome dialog that has to be answered in the OpenTune window; until then every write fails with `BUSY`. See [First launch dialog](TROUBLESHOOTING.md#first-launch-dialog).
- **A check.** `opentune-mcp doctor` checks the set-up without starting OpenTune.

## Reading the tables

Each row is one thing you can ask the agent to do. The second column names the tool (and the operation or mode) the agent uses and the points that matter. The third column says whether the change can be undone and whether the agent must ask you first.

- **Read-only** does not change OpenTune or the project.
- **One undo step** goes into OpenTune's own undo history; the result carries an undo id that `opentune_undo` takes.
- **Cannot be undone** is said in the first sentence of the result, with the way back where there is one. The agent asks you before such a step unless you asked for that very step.
- **No undo entry** is how OpenTune itself works for mute, solo, volume, colour, tempo, time signature and the global settings. The result gives the call that restores the old values.
- **Your agreement** means the agent needs your explicit agreement in the conversation; a tool result never counts. Eight tools are marked destructive in their MCP annotations: `opentune_autotune_range`, `opentune_edit_arrangement`, `opentune_delete_track`, `opentune_manage_ui`, `opentune_open_project`, `opentune_quit`, `opentune_save_project_overwrite` and `opentune_set_settings`. The arguments that confirm such a step (`confirm`, `discard_unsaved`, `replace_edited_notes`, `accept_commit`, `allow_dry`, `allow_second_instance`, `force`) are set only after you agreed.
- **Revision guard.** Write tools take an `expected_revision` that the agent read before (`clip_revision` of a clip, `arrangement_revision` of the arrangement). If you changed the clip in the window in between, the write answers `REVISION_CONFLICT` and the agent reads again instead of overwriting your edit.
- Times are in seconds, and field names state the clock: `content` is the source audio, `timeline` is the arrangement, `output` is after the time grid.

## Arrange clips and tracks

`opentune_edit_arrangement` works on the timeline clock, in seconds. `move`, `trim`, `gain` and `fade` run in order in one call (up to 64 ops) as one undo step. `split`, `merge`, `delete` and `copy` each go alone in a call and cannot be undone. For the first three, the reason is a defect in OpenTune (it frees objects its own undo entry needs); undoing them can make audio vanish, so the agent does not suggest undoing them, in the window either. The agent runs one of them when you named the clip or the time, and asks first when it is unclear which clip you mean.

## Project and saving

OpenTune has no autosave of its own, and the undo history is not stored in the project file. So the agent writes an **autosave copy** after each step, which never touches your project file and needs no question, and overwrites the project file only when you ask or agree. Every save that replaces a project file first keeps the old file as an **old version**. See [Autosave copies and old versions](TROUBLESHOOTING.md#autosave-copies-and-old-versions).

| What you can ask for                    | Tool and key points                                                                                                                                                                                                                                                                                                                                                    | Undo and your agreement                                                                                                                                                 |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Keep a copy of the work after each step | `opentune_save_project` with `mode` `autosave` (needs `project.copy`) writes a numbered copy (`<name>-autosave-0001.otproj`, `-0002`, ...) into `<name>.autosave` next to the project file and keeps the newest 50. It writes nothing outside that folder. The project file, the unsaved-changes flag, the recent-projects list and the window title stay as they are. | Does not change the project file. A project that has no file yet gets an error: save it once with `save_as`. A test build without `project.copy` answers `UNSUPPORTED`. |
| Save the project                        | `mode` `save` overwrites the project file. The file it replaces is first copied into `<name>.oldversion` next to it (the newest 10 are kept); if that copy fails, nothing is saved.                                                                                                                                                                                    | Only when you ask or agree; the agent offers it every few steps and before closing.                                                                                     |
| Save under a new name                   | `mode` `save_as` with an absolute `.otproj` path; the new file becomes the project file. A different existing file is refused.                                                                                                                    | Replaces nothing when the file is new.                                                                                                                                  |

It clears the undo history and old clip ids become invalid.                                       |
| Get earlier work back                   | Open a copy from `<name>.autosave` or a file from `<name>.oldversion` with `opentune_open_project`. An old version finds its audio through the path the save recorded, as long as the project folder was not moved.                                                                                                                                                    | As for opening a project.                                                                                                                                               |

## Undo and redo

| What you can ask for            | Tool and key points                                                                                                                                                                                                                                                                                                                                     | Undo and your agreement                                                                                                                   |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Undo the agent's last change    | `opentune_undo` with the `undo_id` of the step you expect on top, from the result that made it. ## Companion skills

Skills are written instructions that come with the plugin or the extension. They are not extra tools: they tell the agent in which order to work and when to ask you, and the actual work still goes through the tools above. `tuning-workflow` and `check-results` also work in Claude Desktop as uploaded skills. `lyrics-timeline` and `beat-grid` run programs on your computer, so they come with the Claude Code plugin only. See [Install in the README](../README.md#install).

- **`tuning-workflow`** guides the agent through a tuning job in a fixed order: check OpenTune, import the vocal, measure before, decide the key (with `opentune_estimate_key`, also section by section when the key changes), tune with a `dry_run` first, measure after, export and read the peak. It carries the rules of this page: ask for agreement before a destructive step, ask each question once, find out with the tools before asking you, never overwrite your original file, write an autosave copy after each step, and offer a real save every few steps and before closing. It also covers the arrangement, track, transport, window and settings tools, and how to recover from a dialog that blocks writes or from a conflict.
- **`check-results`** checks a tuning result with OpenTune's own analysis (`opentune_analyze_pitch`, not an external pitch tracker), comparing before and after only when both rest on the same kind of target. To check an exported file it asks you, then imports a copy onto an empty track without taking your selection (`opentune_open_audio` with `new_track` and `focus: false`); that import cannot be undone, and you can delete the copy. It undoes a change that went too far and reports in a sentence or two.
- **`lyrics-timeline`** stamps every sung character or word of one or more dry vocal WAV files with a start and end time, so that a request like "raise the first word of the first chorus line by two semitones" can find its notes (with `opentune_get_notes` or `opentune_edit_notes`). Languages: Mandarin, Cantonese, English, German, Spanish, French, Italian, Portuguese, Russian, Korean and Japanese. It runs on your computer; the first use downloads a Python environment and speech models (about 4.7 GB, or about 10 GB with an NVIDIA GPU) only after you agree. The audio is never uploaded, but the lyrics and the timeline are text that the agent reads, so they enter the conversation. Accuracy on singing has not been measured (the aligner was evaluated on speech): treat start times as good to roughly 50 to 150 ms and the end of a held note as rough. The agent asks you where it is unsure.
- **`beat-grid`** measures the tempo and the beat grid of a song, section by section, from its **backing track or original mix** (never from a vocal, which beat trackers handle badly), finds where the grid sits against your vocal, and turns the vocal's note starts into `opentune_edit_timing` batches of up to 64 shifts. It applies one batch at a time and plans again; a clear request to fix the timing counts as your agreement, otherwise it asks first. It does not write section tempi into the project (a project has one tempo). The analyzer (`opentune-beats`, MIT) is a one-time download of about 85 to 90 MB with the default model (about 13 to 15 MB with the small one) from its GitHub Release, only after you agree; every file is checked against a pinned SHA-256. If the install is refused or fails, the skill stops and says so; with only a dry vocal it asks for a BPM, a click track or a MIDI file instead.

## Example scenarios

The sentences in quotes are what you might say. The tool names show what the agent does; you never need to call them yourself. Durations are in [How long to wait](COMPATIBILITY.md#how-long-to-wait). None of the scenarios promises how the result sounds.

### Import, tune to C major, export

- **You say:** "Open `C:\Music\take1.wav`, tune it to C major and export a WAV."
- **The agent does:** `opentune_get_status` (and `opentune_launch` if you agree); `opentune_open_audio`, then `opentune_get_job` until the analysis ends; asks where to save the project and calls `opentune_save_project` with `save_as`; `opentune_analyze_pitch` for the before figures; `opentune_autotune_range` with `regenerate` and the scale C major, first as a dry run, then for real; an autosave copy; `opentune_analyze_pitch` again; `opentune_export_audio` with kind `clip`.
- **You get:** the deviation in cents before and after, the number of flagged notes, the project path and the path of the exported WAV (a taken name gets the next free one), and a reminder that the numbers measure pitch and that listening is up to you.
- **Good to know:** small corrections are barely audible while hybrid mode is on (see [Known limits](#known-limits-and-what-it-does-not-do)). The tuning step is one undo step.

### Fix only the notes that are far off

- **You say:** "Pull back only the notes that are more than 30 cents off and leave the rest alone."
- **The agent does:** `opentune_get_clip_details` to check the clip is analysed and has notes; `opentune_analyze_pitch` with `threshold_cents` 30; `opentune_edit_notes` with a `select` of `off_target_cents_over` 30 and either `snapToScale` or `setParams` with a higher `retune_speed`, as a dry run and then for real; `opentune_analyze_pitch` again.
- **You get:** which notes were flagged, a table of old and new values for each from the dry run, the drop in the number of flagged notes, and the undo id.
- **Good to know:** `opentune_edit_notes` only edits existing notes. If the clip has none yet, import with `generate_notes` or run an auto-tune first.

### Key unknown or changing: estimate first, then tune section by section

- **You say:** "I am not sure which key this song is in. Use the backing track `C:\Music\backing.wav`; if the last chorus modulates, tell me, and tune each part in its own key."
- **The agent does:** `opentune_estimate_key` with `mix_path` and the vocal clip, and again with `sections` around a doubtful boundary; reports the key per part in your terms (times, and the lyric line when a lyrics timeline exists) and asks you to confirm where it is unsure; an autosave copy, because a key change cannot be undone; `opentune_set_clip` sets the longest part's key; one `opentune_autotune_range` per part with that part's `ranges` and an explicit `scale`, each as a dry run first; `opentune_analyze_pitch` per part.
- **You get:** the five best keys with probabilities, a plain statement when relative keys cannot be told apart, the keys along the song, and the before and after figures per part.
- **Good to know:** a clip holds one key, so the other parts are tuned with an explicit scale rather than `"clip"`. Notes that cross a boundary are checked in the dry run. The estimate itself changes nothing.

### Line the vocal up with the beat

- **You say:** "The backing track is `C:\Music\backing.wav`. Is the lead behind the beat? Pull the notes that are more than 30 ms off back onto it."
- **The agent does:** if the analyzer is not installed yet, asks you to agree to the download; the `beat-grid` skill analyses the whole backing track and proposes the tempo of each section for you to confirm; `opentune_get_notes` with `clock` `content` and `output_path`; the skill's `align` finds where the grid sits against your vocal; its `timing-plan` removes the overall lead or lag and lists the onsets still off by 30 ms or more; if the clip has no time handles, `opentune_edit_timing` `seed` (the agent tells you it cannot be undone); then `opentune_edit_timing` `shift` batches, one at a time, reading the notes and planning again after each.
- **You get:** the overall lead or lag in milliseconds, the largest shifts with their times and sections, how many rounds it took, and how to undo each step.
- **Good to know:** the beat measurement needs a backing track or the original mix, not a lone vocal. If you already know the offset ("shift this section 30 ms earlier"), the agent uses `opentune_edit_timing` `shift` directly and no analyzer is needed. Timing edits change when a syllable starts, not how it sounds: listen before and after.

### Try things safely: copies, old versions and undo

- **You say:** "Save a copy after every step, and take back the last change if it went too far."
- **The agent does:** `opentune_save_project` with `autosave` after each finished step; a change that went too far is taken back with `opentune_undo` and its `undo_id`; on `UNDO_CONFLICT` it stops and asks you; before a step that cannot be undone, such as a key change or `notesOnly`, it writes a copy first and tells you that the version before the step is the newest copy in `<name>.autosave`.
- **You get:** the copy folder, the undo result, and the `opentune_redo` call if you want the change back.
- **Good to know:** steps that cannot be undone (see [Known limits](#known-limits-and-what-it-does-not-do)) are the reason for the copies. Going back to the saved state with undo still leaves OpenTune showing the project as modified.

### Rearrange, fade and listen to the vocal alone

- **You say:** "Move the second vocal 0.5 seconds later with a one-second fade-in, then mute the backing track so I can hear the vocal."
- **The agent does:** `opentune_get_project` for the clips' timeline starts and the `arrangement_revision`; `opentune_edit_arrangement` as a dry run, then `move` and `fade` in one call; `opentune_set_tracks` with `mute` on the backing track; and, if you ask, `opentune_transport` with `play`.
- **You get:** the start before and after and the fade length; the mute result with the call that unmutes. OpenTune has no section markers, so the agent names a clip by its start time and asks when two clips fit.
- **Good to know:** a mute has no undo entry, so ask for the track to be unmuted when you are done. Without an audio device nothing is heard.

## Known limits and what it does not do

- **Platform.** Windows x64 with the unofficial test build. macOS: not yet. Linux: not supported (OpenTune has no Linux build). The official OpenTune release has no control interface, so it cannot be used; the VST3/ARA plug-in is not covered. In WSL the server must run with Windows Node.js (see [WSL](../README.md#wsl)).
- **Drawing-style edits.** Drawing, stretching, splitting or merging notes, per-note EQ and hand-drawn pitch curves are not offered, and neither is anything that OpenTune's own window does not have. `opentune_edit_notes` changes existing notes only: it never adds or removes one.
- **No lyrics, no section markers, no beat detection in OpenTune.** The agent locates passages by time, by phrase (`opentune_analyze_pitch` with `detail: phrases`) or, with the `lyrics-timeline` skill, by lyric, and asks when unsure. Beats come from the `beat-grid` skill or from a BPM, click track or MIDI file that you give. A project has one tempo and one time signature.
- **Reference alignment is gone.** OpenTune's upstream project retired the reference track and its AUTO Ref button. The server offers no mode for it (see [COMPATIBILITY.md](COMPATIBILITY.md#reference-alignment-was-removed)).
- **Some edits cannot be undone.** Importing audio, changing a clip's key, a time-grid `seed`, splitting, merging, deleting and copying clips, duplicating and deleting tracks, replacing all notes with `notesOnly`, closing the first-run welcome page and clearing the recent-projects list. Mute, solo, volume, colour, tempo, time signature and the global settings have no undo entry. The result says so in its first sentence.
- **Hybrid mode.** OpenTune's preference "Hybrid Mode" is on by default, and the part of a correction below 75 cents is applied by DSP pitch shifting instead of the vocoder, so a small correction can be barely audible. Ask the agent to switch it off with `opentune_set_settings` (`processing.hybrid_mode`) if small corrections must count; it is a global setting, so, like any other global setting, the agent puts it back to its previous value when the steps are done, unless you ask it to keep hybrid mode off. See [Hybrid mode](TROUBLESHOOTING.md#hybrid-mode).
- **The agent cannot hear.** It gives pitch figures and the effects of operations. Whether a result sounds good, and anything about tone or rhythm feel, is for you to judge. After a tuning step the render needs a moment; the agent checks that it is up to date before it says the result is ready to listen to.
- **Waiting.** Import, analysis, rendering and export take time on long audio; the tools wait for at most 30 seconds and then return a job to follow.
- **Exports.** An export without `path` goes next to the source file; when that folder is read-only it fails and does not choose another folder. Exports are WAV only and never overwrite.
- **Older test builds.** A build without a capability that a tool needs answers that tool with `UNSUPPORTED`. For example, a test build older than specification `1.0.0-rc.8` cannot write autosave copies; then the agent reminds you to save the project when you want to keep your work.
- **Skills that run programs.** `lyrics-timeline` and `beat-grid` download their programs and models only after you agree, work on your computer, and ship with the Claude Code plugin only.
