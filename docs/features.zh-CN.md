# 功能总表

[English](features.md) | **简体中文**

OpenTune MCP Server (by Synchain) 让 AI 客户端操作 OpenTune 独立版,即开源的 AI 人声修音软件。你用平常说话的方式告诉 agent 想怎么改(「把第二句里跑调的音拉准」「把这一段整体提前 30 毫秒」);agent 调用本服务的 28 个工具,做人在 OpenTune 窗口里能做的操作,每个结果都会写明改了什么(带单位的前后值)、有哪些副作用,以及能不能撤销、怎么撤销。

本页按用途列出你可以让 agent 做的事,每一项附上对应的工具和需要注意的地方。它是工具的地图,不是对听感的承诺:结果里的数字只量音准,agent 听不到声音,修得好不好听要你用耳朵判断。每个工具的完整参数见 [reference.md](reference.md)。

## 使用前提

- **带控制接口的 OpenTune 构建。** 官方 OpenTune 发布版还没有控制接口,所以本服务只能配合 OpenTune 的[非官方测试版](https://github.com/synchain-oss/OpenTune/releases)使用(Windows x64)。配官方 OpenTune 时,`opentune_get_status` 报告 `NO_API_BUILD`。测试版使用已安装的官方 OpenTune(1.7.9 或更新)里的模型。安装配置见 [README](../README.zh-CN.md#安装) 与 [install.md](install.md)。
- **只覆盖 OpenTune 独立版。** DAW 里的 OpenTune VST3/ARA 插件不在范围内;与 DAW 之间只通过文件路径交换。
- **测试版要新到够用。** 每个工具都声明了它需要的测试版能力,缺少某项能力的工具会返回 `UNSUPPORTED` 并附下一步,其余工具照常工作。0.2.0 随附的测试版是 `synchain-test/v1.8.0-ctl.2`(规范 `1.0.0-rc.8`),已包含关闭 OpenTune(`app.quit`)、切换视图(`ui.workspace`)和自动副本(`project.copy`)。更早的测试版缺少比它更晚加入的能力。见 [COMPATIBILITY.md](COMPATIBILITY.md#capabilities-of-the-test-build)。
- **首次启动需要有人在场。** OpenTune 用全新数据目录第一次启动时会弹出一个一次性的欢迎对话框,必须在 OpenTune 窗口里回答;在此之前所有写操作都会以 `BUSY` 失败。见 [First launch dialog](TROUBLESHOOTING.zh-CN.md#first-launch-dialog)。
- **自检。** `opentune-mcp doctor` 不启动 OpenTune,只检查上面这些配置。

## 如何读表

每一行是一件你可以让 agent 做的事。第二列写 agent 用到的工具(以及操作或模式)和要点。第三列写这个改动能不能撤销,以及 agent 是否必须先问你。

- **只读** 不改变 OpenTune 或工程。
- **一个撤销步骤** 进入 OpenTune 自己的撤销历史;结果里带一个撤销编号,供 `opentune_undo` 使用。
- **不能撤销** 会在结果的第一句话里说明,有办法还原时一并给出。除非你要求的正是这一步,agent 会先问你。
- **没有撤销条目** 是 OpenTune 本身的行为,涉及静音、独奏、音量、颜色、速度、拍号和全局设置。结果会给出恢复原值的调用。
- **需要你同意** 指 agent 必须在对话里得到你的明确同意;工具结果永远不算同意。有八个工具在 MCP 注解里标为破坏性:`opentune_autotune_range`、`opentune_edit_arrangement`、`opentune_delete_track`、`opentune_manage_ui`、`opentune_open_project`、`opentune_quit`、`opentune_save_project_overwrite` 和 `opentune_set_settings`。用来确认这类操作的参数(`confirm`、`discard_unsaved`、`replace_edited_notes`、`accept_commit`、`allow_dry`、`allow_second_instance`、`force`)只在你同意之后才会设置。
- **版本号保护。** 写工具带一个 agent 之前读到的 `expected_revision`(片段的 `clip_revision`,编排的 `arrangement_revision`)。如果这期间你在窗口里改了这个片段,写操作会返回 `REVISION_CONFLICT`,agent 会重新读取,而不是覆盖你的修改。
- 时间一律以秒为单位,字段名会写明用的是哪一种时钟:`content` 是源音频,`timeline` 是编排的时间线,`output` 是经过时间网格之后的时间。

## 启动、状态与任务

| 你可以让 agent 做的事  | 工具与要点                                                                                                                                                                                                                                                                                                                                                                  | 能否撤销与是否需要你同意                                                                                           |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 检查 OpenTune 能不能用 | `opentune_get_status` 报告一个明确的状态(`READY`、`NOT_READY`、`PROTOCOL_MISMATCH`、`STARTING`、`RUNNING_WITHOUT_API`、`NOT_RUNNING`、`NO_API_BUILD`、`NOT_INSTALLED`、`WSL_UNSUPPORTED_RUNTIME`),并用 `nextStep` 写明下一步该谁做什么。它会列出正在运行的实例(开了多个时 agent 会问你用哪一个),并说明欢迎页或其他对话框是否挡住了写操作(`blockedBy`)。agent 总是先调用它。 | 只读。                                                                                                             |
| 启动 OpenTune          | `opentune_launch` 用控制接口启动配置好的测试版,最多等 30 秒直到就绪。OpenTune 已经在运行时什么也不启动。                                                                                                                                                                                                                                                                    | 再开第二个实例需要 `allow_second_instance`,只在你同意时使用。它从不关闭 OpenTune。                                 |
| 关闭 OpenTune          | `opentune_quit`(需要 `app.quit`)像窗口的关闭按钮一样关闭 OpenTune,并等到它退出。与窗口不同,有未保存的改动时它会以 `UNSAVED_CHANGES` 失败,对话框打开或任务在跑时它会拒绝。在你说做完了的时候用,暂停时不用。                                                                                                                                                                  | 标记为破坏性。`discard_unsaved: true` 只在你同意时使用,丢掉的改动无法找回。想再用时用 `opentune_launch` 重新启动。 |
| 跟踪一个长操作         | `opentune_get_job` 报告一个任务(导入、导出、分析、打开或保存工程)的状态:排队、进行中、成功、失败或已取消,以及进度。`wait_seconds`(最多 30)可以等到它结束。结束的任务保留 30 分钟。                                                                                                                                                                                          | 只读。                                                                                                             |
| 停止一个长操作         | `opentune_cancel_job` 请 OpenTune 停止一个正在运行的任务。任务已经提交的部分会保留:导入会保留已导入的项,导出不会动目标文件。                                                                                                                                                                                                                                                | 不能取消的任务(保存工程、改首选项、过了准备阶段的打开工程)会继续运行,错误里会说明。                                |

## 读取与分析

| 你可以让 agent 做的事      | 工具与要点                                                                                                                                                                                                                                                                                                                                                                                              | 能否撤销与是否需要你同意                                      |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 查看工程                   | `opentune_get_project` 读取工程路径和未保存标记、轨道(音量、静音、独奏)、片段(时间线起止、源文件,以及内容摘要:分析状态、调性、音符数、移调)、当前选中和走带状态。`track_ids` 可以只取部分轨道;`include_history` 会附上撤销与重做历史的栈顶。每个片段带 `clip_revision`,结果带 `arrangement_revision`。                                                                                                  | 只读。                                                        |
| 列出一个片段的音符         | `opentune_get_notes` 按起点顺序分页列出音符(默认 100 个,最多 200 个)。每个音符有序号、内容时钟上的起止时间(放在时间线上的片段还有时间线时钟)、检测到的与目标的 MIDI 音高、偏差(音分)、回调速度、颤音,以及有声与已修正标记。`from` 与 `to` 按 `clock` 指定的时钟限定范围。`output_path` 把该范围内的全部音符存到一个新的 `.json` 文件(`beat-grid` skill 会读它)。                                        | 不改变 OpenTune。带 `output_path` 时只写一个新文件,绝不覆盖。 |
| 读取片段详情               | `opentune_get_clip_details` 读取时长、调性、移调、音高分析状态与最近一次失败原因、当前声音是否已渲染到最新、时间柄,以及 AUTO 模式(AUTO 按钮会跑哪一种、能跑哪些)。`sections` 可以只取 `key`、`pitch_shift`、`analysis`、`render`、`time_grid` 或 `auto_modes`。                                                                                                                                         | 只读。                                                        |
| 量一量音符离准确音高有多远 | `opentune_analyze_pitch` 逐音符给出相对目标的偏差,单位音分(正数 = 偏高)。不带 `corrected` 的字段是检测到的音高减目标(修改之前);`corrected*` 字段是修正后的音高减目标(修改之后)。修音之后它们描述的是修正后的目标曲线,不是对渲染音频的重新测量。偏差超过 `threshold_cents`(默认 25)的音符会被标出。`detail` 取 `summary`、`phrases`(静音超过 0.4 秒就分成两句)或 `notes`;`from` 与 `to` 是源音频的秒数。 | 只读。                                                        |
| 估计一首歌的调性           | `opentune_estimate_key` 可以用人声片段(`clip`),也可以用完整混音或伴奏的 WAV(`mix_path`,绝对路径)。它给出最可能的 5 个调及概率,说明相对大小调(共用同样的 7 个音)分不开的情况,给出整体音高偏移(音分)、随时间变化的局部调,以及 `sections` 里每个时间段(每段至少 2 秒)各自的调,并给出可交给 `opentune_set_clip` 与 `opentune_autotune_range` 的 `recommendation.key`。完整混音或伴奏比单独的人声可靠得多。  | 只读;WAV 只被读取。                                           |

| 把分析失败的片段按未修音状态导出 | `allow_dry: true`。尚未分析好的内容本来就按未修音状态导出;分析失败的片段只有带这个参数才会导出。                                                                                                                                                                                             | 不改变工程。`allow_dry` 只在你同意时使用。 |

## 编排与轨道

`opentune_edit_arrangement` 使用时间线时钟,单位是秒。`move`、`trim`、`gain` 和 `fade` 在一次调用里按顺序执行(最多 64 个操作),是一个撤销步骤。`split`、`merge`、`delete` 和 `copy` 各自单独成一次调用,都不能撤销。前三个的原因是 OpenTune 的一个缺陷(它释放了自己的撤销条目还要用的对象);撤销它们可能让音频消失,所以 agent 不会建议撤销它们,在窗口里撤销也一样。你指明了片段或时间时,agent 会直接执行;不清楚指的是哪个片段时,它会先问你。

| 你可以让 agent 做的事 | 工具与要点                                                                                                                                                                             | 能否撤销与是否需要你同意                                                                                               |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 在时间线上移动片段    | `opentune_edit_arrangement` 的操作 `move`,带 `start_timeline_sec` 和/或 `to_track_id`。它移动片段,不拉伸片段里的音频。                                                                 | 一个撤销步骤(和同一次调用里的 `trim`、`gain`、`fade` 合在一起)。`dry_run` 可预览。该工具因为下面几个操作而标为破坏性。 |
| 裁剪片段的头或尾      | 操作 `trim`,带 `edge`(`start` 或 `end`)和 `to_timeline_sec`。                                                                                                                          | 同上。                                                                                                                 |
| 调整片段增益          | 操作 `gain`,带 `gain_db`。                                                                                                                                                             | 同上。                                                                                                                 |
| 给片段加淡入淡出      | 操作 `fade`,带 `fade_in_sec` 和/或 `fade_out_sec`。                                                                                                                                    | 同上。                                                                                                                 |
| 拆分片段              | 操作 `split`,在 `at_timeline_sec` 处。                                                                                                                                                 | 不能撤销。除非你指明了片段或时间,agent 会先问你。                                                                      |
| 合并两个片段          | 操作 `merge`,带 `leading_clip` 和 `trailing_clip`。无法合并时,结果会说明原因(例如两个片段的调性不同)。                                                                                 | 不能撤销。除非你要求的正是合并,agent 会先问你。                                                                        |
| 删除片段              | 操作 `delete`,带 `clips`;需要 `confirm: true`。                                                                                                                                        | 不能撤销。`confirm` 只在你要求删除或同意删除时使用。                                                                   |

## 工程与保存

OpenTune 自己没有自动保存,撤销历史也不会存进工程文件。所以 agent 在每一步之后写一个**自动副本**,它从不改动你的工程文件,也不需要问你;只有你要求或同意时才覆盖工程文件。每次替换工程文件的保存,都会先把旧文件留成一个**旧版本**。见 [Autosave copies and old versions](TROUBLESHOOTING.zh-CN.md#autosave-copies-and-old-versions)。

| 你可以让 agent 做的事    | 工具与要点                                                                                                                                                                                                                                                                           | 能否撤销与是否需要你同意                                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| 每一步之后留一个工作副本 | `opentune_save_project` 的 `mode` 为 `autosave`(需要 `project.copy`),在工程文件旁的 `<工程名>.autosave` 里写一个带编号的副本(`<工程名>-autosave-0001.otproj`、`-0002` 等),保留最新的 10 个。它不会在该文件夹之外写任何东西。工程文件、未保存标记、最近工程列表和窗口标题都保持原样。 | 不改动工程文件。还没有文件的工程会得到一个错误:先用 `save_as` 存一次。没有 `project.copy` 的测试版会返回 `UNSUPPORTED`。 |
| 保存工程                 | `mode` 为 `save` 时覆盖工程文件。被替换的文件会先复制到它旁边的 `<工程名>.oldversion`(保留最新的 10 个);复制失败就什么也不保存。                                                                                                                                                     | 只在你要求或同意时;agent 会每隔几步以及关闭之前提议保存。                                                                |

| 替换另一个已有的工程文件 | `opentune_save_project_overwrite`,带路径和 `confirm: true`。被替换的文件会存进它旁边的 `.oldversion` 文件夹。                                                                                                                                                                        | 标记为破坏性;那个文件不再是工程文件。`confirm` 只在你同意替换那个文件之后使用。                                          |
| 打开一个工程             | `opentune_open_project`,带绝对路径的 `.otproj`,替换当前工程。它从不保存:有未保存的改动时以 `UNSAVED_CHANGES` 失败(agent 会先写一个副本再问你)。缺少媒体文件的片段会被跳过并列出。                                                                                                    | 标记为破坏性。`discard_unsaved: true` 只在你同意时使用。它会清空撤销历史,旧的片段编号作废。                              |
| 找回更早的成果           | 用 `opentune_open_project` 打开 `<工程名>.autosave` 里的某个副本或 `<工程名>.oldversion` 里的某个文件。只要工程文件夹没有挪动,旧版本就能通过保存时记下的路径找到它的音频。                                                                                                           | 同打开工程。                                                                                                             |

## 附带技能

Skill 是随插件或扩展一起提供的文字说明。它们不是额外的工具:它们告诉 agent 按什么顺序做、什么时候问你,真正的操作仍然经过上面的工具完成。`tuning-workflow` 和 `check-results` 也可以作为上传的 skill 用在 Claude Desktop 里。`lyrics-timeline` 和 `beat-grid` 要在你的电脑上运行程序,所以只随 Claude Code 插件提供。见 [README 的安装一节](../README.zh-CN.md#安装)。

- **`tuning-workflow`** 引导 agent 按固定顺序完成一次修音:检查 OpenTune、导入人声、测修前、定调(用 `opentune_estimate_key`,调性中途变化时按段落分别定)、先用 `dry_run` 再正式修音、测修后、导出并读取峰值。它带着本页的规则:破坏性的步骤先征得同意,每个问题只问一次,先用工具查清楚再来问你,绝不覆盖你的原文件,每一步之后写一个自动副本,每隔几步以及关闭之前提议真正保存。它也涵盖编排、轨道、走带、窗口与设置类工具,以及遇到挡住写操作的对话框或冲突时怎么办。
- **`check-results`** 用 OpenTune 自己的分析(`opentune_analyze_pitch`,不用外部音高检测)检查修音结果,只有在前后两次的目标是同一种时才比较。检查导出的文件时,它先问你,再把副本导入到一条空轨,不抢走你的选中(`opentune_open_audio`,带 `new_track` 和 `focus: false`);这次导入不能撤销,你可以自己删掉这个副本。改过头就撤销,最后用一两句话汇报。
- **`lyrics-timeline`** 给一个或多个干声 WAV 里的每个字或词标上起止时间,让「把第一段副歌第一句里的第一个字升高两个半音」这样的请求能找到对应的音符(用 `opentune_get_notes` 或 `opentune_edit_notes`)。支持的语言:普通话、粤语、英语、德语、西班牙语、法语、意大利语、葡萄牙语、俄语、韩语和日语。它在你的电脑上运行;第一次使用要下载 Python 环境和语音模型(约 4.7 GB,有 NVIDIA 显卡时约 10 GB),你同意后才开始。音频不会上传,但歌词和时间轴是文本,agent 会读取,等于进入了对话。对歌声的精度没有测过(对齐器是在说话语音上评估的):起点请按大约 50 到 150 毫秒的误差看待,长音的结尾更粗略。拿不准的地方 agent 会问你。
- **`beat-grid`** 从**伴奏或原曲混音**(绝不用人声,节拍检测器对人声不可靠)测出一首歌的速度和节拍网格,按段落给出,找出网格相对于你的人声的位置,再把人声各音符的起点变成 `opentune_edit_timing` 的批次,每批最多 64 个 `shift`。它一次应用一批,再重新规划;你明确要求修时间就算同意,否则它先问你。它不会把分段速度写进工程(一个工程只有一个速度)。分析器(`opentune-beats`,MIT)要一次性从它的 GitHub Release 下载,默认模型约 85 到 90 MB(精简版约 13 到 15 MB),你同意后才下载;每个文件都按固定的 SHA-256 校验。如果安装被拒绝或失败,skill 会停下来并说明;只有干声时,它会改为请你提供 BPM、节拍轨或 MIDI 文件。

## 示例场景

引号里的话是你可能会说的。工具名展示的是 agent 实际做的事,你不需要自己调用。耗时见[要等多久](COMPATIBILITY.md#how-long-to-wait)。所有场景都不承诺修出来的声音如何。

### 导入、按 C 大调修音、导出

- **你说:**「打开 `C:\Music\take1.wav`,按 C 大调修音,导出一个 WAV。」
- **agent 做:** `opentune_get_status`(你同意的话再 `opentune_launch`);`opentune_open_audio`,再用 `opentune_get_job` 等到分析结束;问你把工程存在哪里,并用 `save_as` 调用 `opentune_save_project`;`opentune_analyze_pitch` 取修前的数字;`opentune_autotune_range`,模式 `regenerate`、音阶 C 大调,先预演再正式执行;写一个自动副本;再次 `opentune_analyze_pitch`;`opentune_export_audio`,`kind` 为 `clip`。
- **你会看到:** 修前、修后的偏差(音分)、被标出的音符数量、工程路径和导出的 WAV 路径(重名时改用下一个空闲的名字),以及一句提醒:数字量的是音准,好不好听要你自己听。
- **注意:** 混合模式开着时,小幅修正几乎听不出来(见[已知限制与不做的事](#已知限制与不做的事))。修音这一步是一个撤销步骤。

### 只修偏差大的音符

- **你说:**「只把偏差超过 30 音分的音拉回来,其他别动。」
- **agent 做:** `opentune_get_clip_details` 确认片段已分析、已有音符;`opentune_analyze_pitch`,`threshold_cents` 取 30;`opentune_edit_notes`,`select` 用 `off_target_cents_over` 30,操作用 `snapToScale`,或用 `setParams` 提高 `retune_speed`,先预演再正式执行;再次 `opentune_analyze_pitch`。
- **你会看到:** 被标出的音符、预演里每个音符改前改后的值、被标出的音符数量的下降,以及撤销编号。
- **注意:** `opentune_edit_notes` 只改已有的音符。片段里还没有音符时,先在导入时用 `generate_notes`,或先做一次自动修音。

### 调性不确定或中途变化:先估调,再按段落修

- **你说:**「我不确定这首歌是什么调。用伴奏 `C:\Music\backing.wav` 估一下;如果最后一段副歌转调了就告诉我,然后每一段按各自的调修。」
- **agent 做:** `opentune_estimate_key`,带 `mix_path` 和人声片段;对可疑的边界再用 `sections` 估一次;用你的话(时间,有歌词时间轴时还有歌词那一句)汇报各段的调,拿不准的地方请你确认;因为改调不能撤销,先写一个自动副本;`opentune_set_clip` 把片段的调设成最长一段的调;每一段一次 `opentune_autotune_range`,带该段的 `ranges` 和明确指定的 `scale`,每次都先预演;每一段分别 `opentune_analyze_pitch`。
- **你会看到:** 最可能的 5 个调及概率、相对大小调分不开时的明确说明、沿着整首歌的调、每一段的修前修后数字。
- **注意:** 一个片段只有一个调,所以其他段落用明确指定的音阶,而不是 `"clip"`。跨过边界的音符在预演里单独检查。估调本身不改任何东西。

### 把人声对到拍子上

- **你说:**「伴奏在 `C:\Music\backing.wav`。主唱是不是比拍子慢?把偏差超过 30 毫秒的音拉回到拍子上。」
- **agent 做:** 分析器还没装的话,先请你同意下载;`beat-grid` skill 分析整首伴奏,给出各段落的速度请你确认;`opentune_get_notes`,`clock` 取 `content` 并带 `output_path`;skill 的 `align` 找出网格相对于你的人声的位置;它的 `timing-plan` 先扣掉整体的早晚,再列出仍偏差 30 毫秒以上的音符;片段还没有时间柄时,`opentune_edit_timing` 的 `seed`(agent 会告诉你它不能撤销);然后一批一批地 `opentune_edit_timing` 的 `shift`,每批之后重新读取音符、重新规划。
- **你会看到:** 整体早晚的毫秒数、移动最大的音符及其时间和所在段落、一共做了几轮,以及每一步怎么撤销。
- **注意:** 测节拍需要伴奏或原曲混音,不能用单独的人声。如果你已经知道偏移量(「把这一段提前 30 毫秒」),agent 直接用 `opentune_edit_timing` 的 `shift`,不需要分析器。时间修改改变的是音节从哪里开始,不是它听起来怎样:修前修后都听一听。

### 放心试:副本、旧版本与撤销

- **你说:**「每做完一步就存个副本,改过头了就撤销刚才那一步。」
- **agent 做:** 每完成一步用 `autosave` 调用 `opentune_save_project`;改过头时用 `opentune_undo` 和它的 `undo_id` 撤回;遇到 `UNDO_CONFLICT` 就停下来问你;在不能撤销的步骤之前(例如改调或 `notesOnly`)先写一个副本,并告诉你这一步之前的版本就是 `<工程名>.autosave` 里最新的那个副本。
- **你会看到:** 副本所在的文件夹、撤销的结果,以及想把改动要回来时的 `opentune_redo` 调用。
- **注意:** 有些步骤不能撤销(见[已知限制与不做的事](#已知限制与不做的事)),这就是要留副本的原因。撤销回到已保存状态之后,OpenTune 仍然显示工程已修改。

### 调整编排、淡入,再单独听人声

- **你说:**「把第二段人声往后推 0.5 秒,加 1 秒淡入,再把伴奏轨静音,我想单独听人声。」
- **agent 做:** `opentune_get_project` 读出各片段的时间线起点和 `arrangement_revision`;`opentune_edit_arrangement` 先预演,再在一次调用里执行 `move` 和 `fade`;`opentune_set_tracks` 的 `mute` 把伴奏轨静音;你要求的话再用 `opentune_transport` 的 `play` 播放。
- **你会看到:** 移动前后的起点和淡入时长;静音的结果和取消静音的调用。OpenTune 没有段落标记,所以 agent 会用起始时间说明它指的是哪个片段,有两个都像时会来问你。
- **注意:** 静音没有撤销条目,听完请让 agent 把这条轨的静音取消。没有音频设备就听不到声音。

## 已知限制与不做的事

- **平台。** Windows x64 配合非官方测试版。macOS:暂无。Linux:不支持(OpenTune 本身没有 Linux 版)。官方 OpenTune 发布版没有控制接口,不能用;VST3/ARA 插件不在范围内。在 WSL 里,服务必须用 Windows 的 Node.js 运行(见 [WSL](../README.zh-CN.md#wsl))。
- **绘制式编辑。** 绘制、拉伸、拆分或合并音符、逐音符 EQ 和手绘音高曲线都不提供,OpenTune 窗口本身没有的功能也一样不提供。`opentune_edit_notes` 只改已有的音符:它从不新增或删除音符。
- **OpenTune 里没有歌词、没有段落标记、不检测节拍。** agent 按时间、按乐句(`opentune_analyze_pitch` 的 `detail: phrases`),或者借助 `lyrics-timeline` skill 按歌词来定位,拿不准时会问你。节拍来自 `beat-grid` skill,或来自你给的 BPM、节拍轨或 MIDI 文件。一个工程只有一个速度和一个拍号。
- **参考对齐已经没有了。** OpenTune 上游已经退役了参考轨和它的 AUTO Ref 按钮。本服务不提供对应的模式(见 [COMPATIBILITY.md](COMPATIBILITY.md#reference-alignment-was-removed))。
- **有些修改不能撤销。** 导入音频、改片段的调性、时间网格的 `seed`、拆分、合并、删除与复制片段、复制与删除轨道、用 `notesOnly` 替换全部音符、关闭首次引导的欢迎页,以及清空最近工程列表。静音、独奏、音量、颜色、速度、拍号和全局设置没有撤销条目。结果会在第一句话里写明。
- **混合模式。** OpenTune 的首选项「混合模式」默认开启,修正量中小于 75 音分的部分走 DSP 移调而不是声码器,所以小幅修正可能几乎听不出来。想让小修正也明显生效,可以让 agent 用 `opentune_set_settings`(`processing.hybrid_mode`)把它关掉;它是全局设置,和别的全局设置一样,步骤做完后 agent 会把它恢复为原值,除非你要它保持关闭。见 [Hybrid mode](TROUBLESHOOTING.zh-CN.md#hybrid-mode)。
- **agent 听不到声音。** 它给出的是音准数字和操作的效果。修出来好不好听,以及音色或节奏感方面的任何事,都要你自己判断。修音之后渲染需要一点时间;agent 会先确认渲染已经是最新的,才说结果可以听了。
- **等待。** 长音频的导入、分析、渲染和导出需要时间;工具最多等 30 秒,之后返回一个任务编号去跟进。
- **导出。** 不给 `path` 的导出会写在源文件旁;该文件夹只读时导出会失败,不会自动换文件夹。导出只有 WAV,而且从不覆盖。
- **较旧的测试版。** 缺少某个工具所需能力的构建,会让该工具返回 `UNSUPPORTED`。例如早于规范 `1.0.0-rc.8` 的测试版写不了自动副本;这时 agent 会提醒你在想保住成果时保存工程。
- **要运行程序的 skill。** `lyrics-timeline` 和 `beat-grid` 要在你同意之后才下载程序和模型,在你的电脑上运行,并且只随 Claude Code 插件提供。
